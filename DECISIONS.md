# Decisions

Append-only. One line per settled decision, newest last. If it isn't here, a
future session will re-litigate it.

| date | decision | reason |
|---|---|---|
| 2026-09-08 | Brand: **Calibrated Sports** | Names the differentiator; nobody publishes calibration curves. Rejected Empirical (category word), Actuarial (insurance connotation), Moment/Axiom (taken) |
| 2026-09-08 | Fully separate from Praxis — own repo, domain, DB, VPS, credentials | Public brand vs private infra; blast-radius isolation; clean deploy story for hiring |
| 2026-09-08 | Storage: SQLite until a second sport or second writer | Zero infra, handles a season at these cadences. Postgres is premature |
| 2026-09-08 | Hosting: Render worker for the logger initially | Known deploy story; a dedicated droplet later without deadline pressure |
| 2026-09-08 | Odds API = scheduled snapshots keyed to kickoff, not polling | Per-event prop calls bill credits; CLV needs the close, not a tick history |
| 2026-09-08 | Public site uses free data only; PFF (if bought) stays in `edge/` | PFF terms bar public display and derivative works; a repo depending on licensed data isn't reproducible, which undercuts the hiring artifact |
| 2026-09-08 | Priority markets: targets, rush attempts, receptions | OOS R² 0.277 / 0.254 / 0.234 vs 0.145 yards, ~0.05 TDs, 0.039 QB attempts |
| 2026-09-08 | Build the scoreboard before the model (brief 004) | A naive baseline measured end to end beats a good model with no measurement |
| 2026-09-09 | Kalshi discovery = `/series?category=Sports` -> filter -> per-series `/markets` | Walking `/markets` by cursor never reaches sports (~13,900 series; the page cap trips first). Series catalogue cached 24h - it is 5.7MB and changes on the order of days |
| 2026-09-09 | NFL filter guards on category AND a ticker/title match | "inflation" contains "nfl" (matches every CPI series), "NFLX" is Netflix, and `KXNCAAFCONFLEAVE` contains it across a word boundary. Category alone admits college football |
| 2026-09-09 | Kalshi prices are DOLLARS and need no conversion | `yes_bid_dollars: "0.1800"`; a contract settles at $1 so the dollar price is the probability. The old cents divisor put every price 100x low |
| 2026-09-09 | Kalshi orderbooks batched with REPEATED `tickers` params | Comma-joined returns HTTP 200 with one empty book named after the joined string. Silent - reads as "no liquidity". 100 tickers per call is the ceiling (150 -> 400) |
| 2026-09-09 | Track a Kalshi series allowlist, not all football | All 349 NFL series carry 16,756 open markets; at these cadences that is GB/day and fills the disk in under a day. Allowlist = game core + receptions + rush attempts + SGP pre-packs + season futures = ~3,000 markets. `KALSHI_ALLOWLIST_OFF=1` reverses it |
| 2026-09-09 | Polymarket discovery = `/events?tag_slug=nfl`, 422 is soft | Blind `/markets` pagination 422s at offset 2100 ("use /markets/keyset"); football sits past it. Tag-filtered events page cleanly to 588 in 6 calls. A 422 truncates discovery, never kills it |
| 2026-09-09 | Polymarket quotes from `POST /clob/prices`, not the gamma payload | Gamma carries bestBid/bestAsk inline, so discovery quotes are free - but refreshing that way archives ~26GB/day to carry 3 numbers per market. The CLOB reports identical top-of-book in 21KB per 250 markets, and updates faster |
| 2026-09-09 | Write a quote row on price change, plus a forced heartbeat every 5 min | Dedupe alone makes "price held steady" and "logger was down" the same absence, so a missing T-5min close looks like a quiet one. `poll_log` catches venue outages, not one market dropping out of discovery. Cut a 20s cycle from 1,697 rows to ~30 |
| 2026-09-09 | One rate limiter per venue, Kalshi at 10 rps | A shared bucket made Kalshi's discovery pass starve the 15s hot tier. Kalshi Basic allows ~20 req/s; backoff stays blind, there is no Retry-After on their 429 |
| 2026-09-09 | Raw archive is ROTATED to Cloudflare R2 at 7 days, never deleted | Invariant #2 makes the archive the thing every derivation is re-runnable from. Rotation is hash -> upload -> verify by reading the bytes back -> delete local -> mark remote. A failed verify keeps two copies; the state "local gone, remote unverified" is unreachable |
| 2026-09-09 | Verify by downloading and hashing, not by trusting a 200 | An ETag on a multipart upload is not the MD5 of the content, so it compares against nothing we computed. R2 egress is free and a shard rotates once, so the honest check is affordable |
| 2026-09-09 | `raw_shards` manifest is the answer to "where is that hour?" | rel_path, sha256, bytes, state, bucket/key, uploaded/verified/deleted timestamps. Without it a rotated archive is a set of files nobody can locate |
| 2026-09-09 | Below DISK_MIN_FREE_GB the archive stops, the logger does not | A quote row is a few hundred bytes and is what the scoreboard reads; a raw payload is a megabyte and is what fills a disk. A logger that dies on a full disk loses the hours it exists to capture. Recorded in `source_health`, degradation is visible not silent |
| 2026-09-09 | `quotes` is the only table that may be pruned outright (21 days) | It is derived - every row was parsed from an archived payload, so the archive re-produces any window. `poll_log` and `markets` are kept: poll_log is the coverage record and is how gaps stay visible |
| 2026-09-09 | Dead-man switch at 20 min, plus per-venue staleness | A crash is loud and gets restarted. The failure that matters is the process that stays up and quietly stops capturing - an expired session, a venue that moved a filter - which from outside is identical to a healthy logger on a quiet night |
| 2026-09-09 | Rotation and pruning run inside run_logger, not only from cron | The requirement is surviving three weeks of neglect. Retention that works only when somebody remembers to install a cron entry does not survive neglect, it just relocates the failure. Both stay independently runnable as `python -m jobs.*` |
| 2026-09-09 | Quotes retention 14d, not 21d | Measured: raw **1.10 GB/day** gzipped + quotes **0.61 GB/day** = **1.71 GB/day** (11.7 min window, quiet midweek, no hot tier). Local ceiling with rotation at 7d and quotes at 14d: 7.7 + 8.5 = **16.2 GB steady state**, vs 26 GB free on this box. 21d put the ceiling at 20.4GB against 26GB free, inside the noise of a game-day week; 14d leaves real margin |
| 2026-09-09 | nflverse weekly stats come from the `stats_player` release, not `player_stats` | `player_stats` froze on 2025-05-07 with no 2025/2026 assets. Pointing there stops receptions/targets/carries at 2024 while every job still reports healthy. Verified live: `stats_player` carries all 27 seasons |
| 2026-09-09 | The missing-2019 weekly file needs no special case | It is an artifact of the frozen release. `stats_player_week_2019.parquet` exists on `stats_player` like every other season; the workaround was for a release that stopped being maintained |
| 2026-09-09 | Schedules come from `schedules/games.parquet`, not the raw github CSV | Identical 46 columns and 7,548 rows, 1999-2026, but it is a release asset so it goes through the same archive and manifest path as everything else. Carries closing spread/total/moneyline on 7,376 rows back to 1999 |
| 2026-09-09 | `store.archive_file()` for binary, alongside `archive_raw()` for JSON | archive_raw json-encodes into gzipped JSONL; a parquet file cannot survive that, and re-encoding would break "archive verbatim" anyway. Same manifest, health and disk plumbing, different primitive. Writes via temp-and-rename |
| 2026-09-09 | A new dated copy is stored only when the BYTES change | Daily dated snapshots of 27 seasons would be ~265GB/year and would bury the handful of real stat corrections among 364 identical copies. Hash, compare, record the check. Measured corpus after full backfill: **592MB**, matching the brief's "under 1GB" |
| 2026-09-09 | nflverse raw is exempt from rotation (`RAW_ROTATE_EXEMPT`) | Those dated snapshots ARE the defence against a stat correction rewriting history; shipping them to R2 and deleting locally after 7 days defeats the reason for mirroring. Market data is the storage problem, this is a rounding error |
| 2026-09-09 | Normalize weekly stats, games and snap counts into SQLite; archive the rest | Those three serve the acceptance query and the game-line backtest. pbp (150+ cols, 20MB/season), NGS, FTN and participation are archived verbatim and read with polars - flattening them is deferred, not forgotten |
| 2026-09-09 | Offseason-tier fields raise via `nflverse.require_live()` | participation does not refresh in-season, so a feature reading `route` or `was_pressure` works in April on 2024 and is silently empty in October. Nulls look like a quiet player, not a bug - raising is the only version that gets noticed |
| 2026-09-09 | "Not published yet" is a healthy outcome, not a failure | On 2026-09-09, the day before the opener, pbp/snaps/FTN/participation/weekly_stats had no 2026 asset at all. Treating that as an error pages somebody nightly through August |
| 2026-09-09 | Logger refreshes the live tier for the CURRENT season only, every 6h | Re-checking 27 seasons 4x/day is 2.4GB/day of downloads to rediscover that 1999 has not changed. 6h covers the fastest cadence the brief asks for (snaps, FTN) |
| 2026-09-09 | The dead `player_stats` release did NOT corrupt the research findings | A/B with methodology held fixed: every market within 0.012 OOS R2 (rush att .517 vs .529, targets .489 vs .492, receptions .402 vs .405), identical ordering. Only 2019 differed materially upstream and its effect was a ~2% smaller training sample |
| 2026-09-09 | The 2019 legacy file was the offense-only product, not a shape change | `player_stats_2019.parquet` is weekly but carries 617 players vs 1,891 in `stats_player_week_2019`. Reception totals match within 2, so it is a subset of productive players, not aggregated data. Every other season matched within 2 rows |
| 2026-09-09 | Priority market SET re-validated on unseen 2025; internal order unresolved | targets / rush attempts / receptions are the top three in both windows, both data sources and both position-pool definitions, far above yards, TDs and QB props. The decision is unchanged |
| 2026-09-09 | The original research methodology is LOST and must be rebuilt before levels mean anything | No `research/` dir, notebook or saved fit ever existed - only the figures. A reconstructed usage-only baseline reproduces the priority set but sits ~0.2 R2 above the reference and ranks rush attempts first. Levels and internal order cannot be compared until the original spec is recovered or replaced |
| 2026-09-09 | Distribution FAMILY holds, PARAMETERS do not reproduce | Overdispersion, right skew and non-trivial P(0) confirmed on 2025 under every filter tried - negative binomial and zero-inflated gamma stand. But measured receptions mean 2.3-3.2 vs 3.75 reference and var/mean 1.8-2.3 vs 1.69; carries 7.5-9.3 vs 12.1. `core/distributions.py` and `tests/test_core.py` hardcode the reference values - do not trust them as measured until the sample screen is recovered |
| 2026-09-09 | Same-game correlations hold on unseen 2025 | QB<->WR1 0.442 (ref 0.42), WR1<->WR2 0.103 (ref 0.02) on 406 team-games; 0.491 / -0.007 on the 2023-24 window. Near-zero WR1<->WR2 confirmed - a diagonal covariance is still wrong for QB<->WR1 |
| 2026-09-09 | R2 rotation is live and the wire path is verified, not just unit-tested | `--check` preflight round-tripped a real object (upload, head, read-back, sha256, delete) and a full cycle moved a real 2.9MB shard: verified, local copy reclaimed, manifest state=remote. Closes the gap left when credentials were absent |
| 2026-09-09 | `local_shards()` sees every archived file, not only `.jsonl.gz` | The extension filter made `--status` report "exempt: 0 shards" while 566MB of exempt nflverse corpus sat on disk - the one line whose job is to prove that corpus is protected. Protection is `is_exempt()`'s job; enumeration must see everything |
| 2026-09-09 | The healthcheck ping is emitted from the watchdog, gated on the dead-man switch | Pinging from the poll loop would create two code paths answering "is this capturing?" separately, and the failure that matters is where they disagree - a logger reassuring an external monitor while its own switch is tripped |
| 2026-09-09 | A tripped switch SKIPS the ping rather than sending `/fail` | Silence is what healthchecks turns into an alert on its own timer, and silence also covers what a self-report never can: killed process, wedged loop, dead box. Period 20m / Grace 5m matches DEADMAN_MIN |
| 2026-09-09 | Liveness only considers venues this process is running | poll_log keeps history forever, so a venue switched off last week would otherwise read as permanently stale and silence the external monitor for good |
| 2026-09-09 | A single stale venue suppresses the ping | Partial capture is not capture. One venue dropping out of discovery while others keep the global timestamp fresh is exactly the quiet failure the switch exists for |
| 2026-09-09 | TACKLES+ASSISTS = solo + with_assist + assists; box-score SOLO = solo + with_assist | Verified against ESPN, three player-games. Two cases were not enough: both had with_assist=0, which leaves "solo+assists" looking right while being off by up to 3 tackles on ~6% of defensive player-games. `research/tackle_definition.py` |
| 2026-09-09 | nfl_player_week rebuilt from the LOCAL archive, not re-fetched | Invariant #2 collecting on its promise: widening a projection is a re-parse. 27 shards, no network, each re-normalized under its original data_version so a parser change manufactures no new version |
| 2026-09-09 | Venues disagree on the calendar day of a night game | Kalshi and nflverse date the 2026 opener 09-09 (Eastern); Polymarket says 09-10 (UTC, kickoff 00:20Z). Keyed on the venue's own date, one game forks into two weeks or fails to resolve. `game_for` matches the team pair exactly and the date within a day |
| 2026-09-09 | Name ambiguity is broken on facts, never on similarity | "DeVonta Smith" (WR) and "Devonta Smith" (CB) collide after normalization. Tiebreak order: recorded a snap that season, then roster status. Still ambiguous = unmapped with a reason. There is no fuzzy matching anywhere in the system |
| 2026-09-09 | Every logged market gets a market_outcome row, mapped or not | Coverage computed over only the markets you managed to parse is not a coverage number, and the unmapped list grouped by reason is the queue that says which mapper to improve next |
| 2026-09-09 | Settlement is versioned by the data_version it was computed from | A stat correction writes a SECOND settlement row rather than editing the first. Settling a prop is when a backtest's P&L becomes real; a silently restated settlement is a silently restated track record |
| 2026-09-09 | Brief 003 coverage: kalshi 1,743/3,091 (100% of every non-future type), polymarket 1,678/4,742, 263 outcomes cross-venue | Unmapped remainder is season-long slugs, futures, quarter/half segments and oddsapi discovery rows - all recorded with reasons |
